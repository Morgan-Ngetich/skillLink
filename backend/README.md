# Backend

Built with **FastAPI + PostgreSQL + RabbitMQ + Celery + Redis**, fully containerized with Docker.

---

## Project Structure

```
backend/
├── app/
│   ├── api/           — Route handlers

│   ├── services/      — Business logic
```

## Quickstart

All backend services — FastAPI, PostgreSQL, RabbitMQ, Redis, and Celery — are fully containerized. Everything starts with a single command from the project root:

```bash
docker compose build
docker compose up -d
```

| Service | URL |
|---------|-----|
| API | http://localhost/api/v1 |
| Swagger Docs | http://localhost/docs |
| RabbitMQ Management | http://localhost:15672 |

## Migrations

All migrations are run manually. They are **not** applied automatically on startup.

### 1. Exec into the backend container

```bash
docker exec -it backend sh
```

> If the backend container is down, start a temporary one instead:
> ```bash
> docker run -it --entrypoint sh backend
> ```

### 2. Generate a migration

After making model changes, generate a new migration script:

```bash
alembic revision --autogenerate -m "your message here"
```

### 3. Validate the migration script

Before applying, open the generated file in `alembic/versions/` and verify:
- The `upgrade()` function reflects your intended schema changes
- The `downgrade()` function correctly reverses them
- No unintended tables or columns are being dropped

> Autogenerate is not perfect — always review the script before running it.

### 4. Apply migrations

```bash
alembic upgrade head
```

### 5. Commit the migration

Always commit the generated migration file alongside your model changes:

```bash
git add alembic/versions/
git commit -m "add migration: your message here"
```

> Never apply a migration without committing it. Other developers and environments depend on the migration history being in sync.

## Dependency Management (Poetry)

Dependencies are managed with **Poetry**. Never manually edit `pyproject.toml` or install packages with `pip`.

### Adding a new dependency

```bash
# 1. Navigate to the backend directory
cd skillLink/backend

# 2. Activate the Poetry virtual environment
poetry shell

# 3. Add the dependency
poetry add package-name

# 4. Restart the backend container to apply changes
docker compose restart backend
```

> After adding a dependency, the `pyproject.toml` and `poetry.lock` files will be updated. Commit both files.

## Tests

Tests run against a dedicated test database in an isolated container.

### Start the test database

From the **root of the repository**:

```bash
docker compose -f docker-compose.test.yml up -d
```

### Run tests

```bash
docker exec -it backend pytest
```

> Make sure the backend container is running and the test DB is healthy before running tests.

## Common Docker Commands

| Command | Description |
|---------|-------------|
| `docker compose up -d` | Start all services in the background |
| `docker compose build` | Rebuild containers after Dockerfile changes |
| `docker compose restart backend` | Restart the backend container |
| `docker compose logs -f backend` | Stream backend logs |
| `docker compose down` | Stop and remove all containers |
| `docker exec -it backend sh` | Shell into the backend container |
| `docker compose exec db sh` | Shell into the database container |

## Notes

- All migrations must be run manually inside the backend container — they are not applied automatically on startup.
- Always review autogenerated migration scripts before applying them.
- Always commit migration files alongside model changes.
- When adding dependencies, always use Poetry. Direct `pip install` will not persist inside the container.
- The Celery worker runs as a separate container and picks up tasks via RabbitMQ automatically on startup.
